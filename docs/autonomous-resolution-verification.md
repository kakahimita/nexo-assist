## Resulting behavior

Mastra remains the live reasoning engine. Prompt `consultation-v7` requires applicable knowledge lookup, concrete steps, an outcome check, acknowledgement of successful resolution, and proactive draft preparation when safe self-service is exhausted. Missing classification facts are collected without requiring an opening command or repeating already-supported answers. The server still derives classification, authenticates the employee, checks duplicates, requires current-draft confirmation, and performs idempotent writes.

`requiresAnalyst` is validated tool metadata, stored on the draft proposal run. It never writes a ticket by itself. After confirmation, the backend associates the actual ticket with the conversation and durably queues it. `handoffCompleted` prevents retried confirmations from transferring twice or interrupting an explicit analyst return. Cancelled, stale and unauthorized confirmations cannot queue the conversation. Existing databases receive two default-false columns through an additive migration.

The analyst summary includes the initial report, latest message and recent conversation, within the existing 2,000-character wire limit. The live long-history case exposed this limit after the ticket commit; retrying the same confirmation after the fix completed the transfer without creating a duplicate. Quick replies cannot impersonate confirmation/edit/cancel controls. Live generation has a 60-second budget; quota errors remain explicit and human contact remains available.
